Use the right severity — every time
Misused log levels make noise that drowns out real incidents. Set your default production level to INFO and use a dynamic flag to enable DEBUG without redeploying.
DEBUG
Fine-grained diagnostic info for developers. Never ship to production at high volume — use sampling or a feature flag. Good for: SQL queries, cache hit/miss, internal state dumps.
INFO
Routine operational events: service starts, config loads, request completions, cron job runs. Should read like a narrative of what the system is doing.
WARN
Something unexpected happened but the system recovered. Retries succeeded, deprecated API called, rate limit approaching. WARNs should trigger investigation, not pages.
ERROR
An operation failed. A request returned 5xx, a write to disk failed, an external call timed out. Always include the full exception / stack trace. Errors should page on-call.
FATAL
The process is about to crash. Used for unrecoverable states: out of memory, corrupted config, required service unreachable at startup. Emit, then exit.
Dynamic log level control
Expose a runtime endpoint to change log level without restart — critical for debugging production issues without redeployment. Common pattern: POST /admin/log-level {"level":"DEBUG"} guarded by an internal-only network rule.
Always emit JSON — never free-form strings
Structured logs are machine-parseable, filterable, and aggregatable. Every log line should be a valid JSON object with a consistent set of mandatory fields.
Mandatory fields on every log line
"timestamp": "2024-03-15T08:34:22.419Z", // ISO 8601 UTC, milliseconds "level": "INFO", "service": "payment-svc", // from env var at startup "env": "production", "host": "ip-10-0-4-22", "trace_id": "a1b2c3d4e5f6...", // propagated from upstream "span_id": "f1e2d3", "message": "Payment processed", "duration_ms": 142
Correlation IDs
Generate a trace_id at the edge and propagate it as an HTTP header (X-Trace-Id) through every service call. Log it on every line so you can reconstruct a full request across 10 microservices.
Context enrichment
Use structured context objects per request (MDC in Java, context vars in Python). Fields like user_id, tenant_id, request_id should be set once and auto-attached to every log line in that request scope.
What not to log
Never log passwords, API keys, session tokens, or full credit card numbers — even by accident via object serialisation.
Avoid logging full request/response bodies in production. Use field-level allow-lists when you need partial bodies.
Don't log PII (email, name, IP) without explicit legal basis. Pseudonymise or hash where possible.

Always write to stdout
Apps should log to stdout/stderr only — never write to local files. The container runtime or host agent captures it. This keeps your app stateless and lets orchestrators (k8s, ECS) handle log routing.
Use a buffer queue in production
Insert Kafka or Kinesis between your shipper and storage. This absorbs traffic spikes, lets you replay logs after a sink failure, and decouples producers from consumers.
Parse at collection time, not query time
Parse and normalise log fields when the shipper ingests them. Late parsing is expensive at query time and brittle when log formats change. Store structured data, not raw strings.
Log sampling for high-cardinality sources
For services emitting >10k lines/sec, use head-based sampling (log 1 in N) for DEBUG/INFO, but always log 100% of WARNs and ERRORs. Sampling decisions must be propagated via the trace context.
Tiered retention cuts cost dramatically
Log storage is often the largest observability cost. Use a hot/warm/cold model aligned to your incident response and compliance requirements.
Retention tiers
Hot
0–7 days. Full-resolution, indexed, sub-second queries. Stored in your search cluster (OpenSearch, Datadog, Loki). Most expensive tier — only keep what on-call engineers actually query during incidents.
Warm
7–30 days. Compressed, partially indexed. Queries take seconds to minutes. Good for trend analysis and post-mortems. Use index lifecycle policies (ILM in Elasticsearch) to auto-migrate.
Cold
30 days – N years. Gzip-compressed raw JSON on object storage (S3 / GCS). Query with Athena or BigQuery when needed. ~$0.023/GB/month. Ideal for compliance archival.
Compliance-driven minimums
SOC 2: 1 year minimum for audit logs
PCI DSS: 1 year, 3 months hot
GDPR: define and document your retention period — then enforce it via auto-delete policies
Cost reduction tactics
Drop health-check logs at the shipper level — they're 20–40% of volume in most Kubernetes clusters.
Compress with Zstd (better ratio than gzip) before sending to cold storage.
Route DEBUG logs directly to cold storage, bypassing the hot index entirely.
Alert on log patterns, not just metrics
Good log-based alerting catches issues that metrics miss — unexpected error messages, authentication anomalies, config parse failures. The goal: high signal, low noise.
Error rate threshold
Alert when ERROR log rate exceeds X% of total log volume in a rolling 5-minute window. Use a percentage, not an absolute count, to handle traffic variance.
Absence alerting
Alert when expected logs stop arriving — e.g., a cron job that should log "completed" every hour. Silence is often more dangerous than errors.
Pattern matching
Alert on specific strings: "OOM killed", "disk full", "certificate expired". These are precise and actionable — zero false positives.
Anomaly detection
Use statistical baselines (e.g. WARN volume is 10× the weekly average for this hour). Catches gradual degradation that fixed thresholds miss.
Fighting alert fatigue
Every alert must have a runbook. If an engineer can't act on it, it's noise — delete it.
Group related alerts. 20 alerts from the same root cause should be one page with context.
Set different severities: P1 (page immediately) vs P3 (Slack notification, business hours only).
Review and prune alerts monthly. Keep the signal-to-noise ratio above 80%.
Log security is part of your security posture
Logs are a primary forensic artifact. They need protection, integrity guarantees, and controlled access — especially in regulated environments.
Access control
Apply RBAC to your log platform. Engineers can query logs for their service. Security team can query across all services. No one can delete logs except automated retention policies.
Immutability
Write logs to an append-only store (S3 Object Lock, Cloudwatch Log Groups with immutability enabled). Prevents log tampering after a breach — a requirement for most compliance frameworks.
Encryption in transit and at rest
TLS 1.2+ for all log transport. Encrypt cold storage with customer-managed keys (CMK) in KMS. Rotate keys annually at minimum.
Audit logging
Log all access to your log platform itself. Who queried what, when. Cloud-native audit logs (CloudTrail, GCP Audit Logs) are your first line — enable them everywhere.
PII and sensitive data
Implement a log scrubbing layer at the shipper that regex-scans for patterns like credit cards, SSNs, and email addresses and replaces them with [REDACTED].
Use a tokenisation service: replace user_id=12345 with a pseudonym that can only be reversed by the privacy team with the right key.
Run periodic scans on your log storage to detect PII that slipped through — tools like AWS Macie or open-source presidio work well here.
Shippers & collectors
VectorOSS
High-performance Rust-based shipper. Best choice for new setups — lower resource use than Fluentd, rich transforms built-in.
Fluentd / Fluent BitOSS
Battle-tested, huge plugin ecosystem. Fluent Bit is the lightweight sidecar version for Kubernetes pods.
OpenTelemetry CollectorOSS
Vendor-neutral. Handles logs, metrics, and traces in one agent. Ideal if you want a unified observability pipeline.
Storage & indexing
Grafana LokiOSS
Index-free log aggregation — only indexes labels, not content. 10× cheaper than Elasticsearch at scale. Integrates natively with Grafana dashboards.
OpenSearchOSS
Full-text search on any field. Great for unstructured logs or complex queries. Higher cost per GB than Loki.
CloudWatch LogsManaged
Zero-ops on AWS. Use Log Insights for ad-hoc queries, export to S3 for cold storage. Best for AWS-native stacks.
DatadogManaged
Full observability platform: logs, APM, metrics unified. Expensive at volume but powerful correlation across signals.
Queue / buffer
Apache KafkaOSS
Industry standard for high-throughput log pipelines. Run on MSK (AWS) or Confluent Cloud to reduce ops burden.
Amazon KinesisManaged
Managed, AWS-native. Simpler than Kafka for pure AWS environments. Scales automatically.
